# Схема PayEngine

Учебный движок. Касса задаётся JSON-файлом, а не кодом. На старте движок читает каждый `integrations/*.json`, проверяет слова и один раз собирает план. Дальше по этому плану он собирает HTTP-запрос, читает ответ и разбирает колбэк.

Незнакомый ключ, слово закрытого списка или подстановка — ошибка, в тексте есть путь до места. Такая запись не отбрасывается молча. Второй раз план не собирается.

Корень файла — объект `Providers`. Имя секции — латиница. Образец формы — `integrations/example.json`, фирма в нём `firm-a`. Секрет в определение не пишется: в кредах стоит ссылка `$secret:Секция:Поле`, пустое значение лежит в `appsettings.example.json`.

## Поля секции

`Code` — короткий код секции. `DisplayName` — имя для человека. `Firms` — список фирм; у образца это `firm-a`. `Capabilities` — что секция умеет делать. `BaseUrl` — начало адреса, без хвоста пути. `TimeoutSeconds` — сколько секунд ждать ответ. `Notes` — одно решение, которого из остальных полей не видно. Нет такого решения — ключа нет. `Masking` — имена полей ответа, которые в журнале прячут: `Partial`, `Full`, `Wrapped`, каждое список строк. Движок списки проверяет и в журнал ничего не пишет.

`Accounts` — именованные наборы кредов. Метод ссылается на набор по имени. Значения полей — ссылки на секреты.

`Auth` — как назваться на исходящем вызове. Это не подпись.

`Signing` — подпись исходящего вызова и подписи колбэков.

`Payin` и `Payout` — приём и выплата. Форма одна: `Create`, `Response`, `Callback`.

`PaymentMethods` — таблица методов. Ключ — код метода. Значение говорит, как метод называется у кассы и в каких границах суммы он живёт.

## Auth

`Auth.Kind` — одно из трёх слов.

| Kind | Что делает |
| --- | --- |
| `None` | Заголовок авторизации не ставится. |
| `Bearer` | Заголовок `Authorization: Bearer` и текст из `Value`. |
| `Header` | Свой заголовок: имя в `Header`, текст в `Value`. |

`Value` обычно берётся из креда, например `{account.ApiKey}`.

## Signing

Три блока одной формы: `Signing.Request` (исходящий вызов, он общий для приёма и выплаты), `Signing.PayinCallback`, `Signing.PayoutCallback`. Запрос и колбэк могут подписываться по-разному.

Поля блока: `Algorithm`, `Base`, `Encoding`, `Key`, `Header`, `BodyField`, `Required`.

`Algorithm`: `None`, `HmacSha256`, `HmacSha512`, `Md5`, `Sha256`. `None` значит, что подписи нет. `HmacSha256` и `HmacSha512` считают HMAC от базы ключом `Key`. `Md5` и `Sha256` — хеш самой базы.

`Encoding`: `HexLower`, `HexUpper`, `Base64`. Так байты подписи становятся текстом.

`Header` — имя заголовка, куда кладётся подпись запроса. `BodyField` — поле тела с той же подписью. `Required` на колбэке говорит, обязательна ли верная подпись.

`Base` — что именно подписывается. Базы три.

- `{body}` — сырое тело, как оно ушло или пришло.
- `{body:kv}` — имя поля написано сразу за его значением, знака `=` нет. Поля идут в том порядке, в каком уходят. Поле, куда пишется сама подпись, в строку не входит.
- `{body:query}` — пары `имя=значение`, между парами стоит `&`. Ключи идут по возрастанию кодов символов. Поле `sign` и пустые значения не входят, число ноль остаётся. Значения для URL не кодируются.

Других баз нет. Чего движок не умеет — в конце этого файла.

## Create

`Payin.Create` и `Payout.Create` описывают исходящий вызов.

`Path` — путь без ведущего слэша, он клеится к `BaseUrl`. `Verb` — глагол HTTP. `ContentType` — `Json` или `Form`. `Headers` — дополнительные заголовки. `Body` — поля тела.

Значение поля — строка. Префикс меняет тип: `num:` отправляет число, `bool:` отправляет булево. Без префикса уходит строка.

Имена в фигурных скобках подставляются при сборке. Движок знает такие:

- `{attemptId}` — идентификатор попытки;
- `{sum}` — сумма в основных единицах;
- `{sum:minor}` — та же сумма в минимальных единицах;
- `{currency}` — валюта метода;
- `{callbackUrl}` — адрес, на который касса пришлёт колбэк;
- `{method.ProviderMethod}` — имя метода у кассы;
- `{account.*}` — поле креда, например `{account.ApiKey}`;
- `{now:unix}` — текущее время, секунды;
- `{clientPhone}` — телефон плательщика.

Незнакомое имя в скобках роняет загрузку. В провод оно литералом не уходит.

## Response

`Payin.Response` и `Payout.Response` читают ответ create.

`PaymentId` — откуда взять идентификатор платежа у кассы. `Redirect` — страница, когда реквизита нет. `ErrorCode` и `ErrorMessage` — слова кассы об ошибке.

`Outcome` — список правил. У правила есть `When`, `Result`, `Code`, `Message`. Берётся первое правило, чьё `When` совпало. `Result` — одно из `Accepted`, `Declined`, `Error`.

`When` собирается из таких кусков. Связка между ними только `and`:

- `http:2xx` — любой ответ с кодом 200–299;
- `http:NNN` — один код, например `http:422`;
- `$.путь == значение` — поле тела равно значению;
- `$.путь exists` и `$.путь missing` — поле есть или его нет;
- `$.путь in [a, b]` — значение входит в список.

`Requisites` — ветви реквизита. Тип ветви: `Card`, `Phone`, `BankAccount` или `Qr`. У ветви есть `When` и место, откуда берётся значение. Ветви проверяются по порядку, остаётся первая, которая дала значение.

Исход платежа — это значение `Accepted`, `Declined` или `Error`. Исключением исход не сообщается.

## Callback

`Payin.Callback` и `Payout.Callback` разбирают входящий колбэк. Это отдельная таблица, не ответ create.

`Format` — `Json` или `Form`. `AttemptId`, `ProviderPaymentId` и `Status` — откуда читать эти поля. `Amount` — сумма в колбэке, если касса её прислала. `AmountUnit` — `Major` или `Minor`: основные единицы или минимальные. Пустой `AmountUnit` значит `Major`.

`StatusMap` переводит слово кассы в одно из `PaymentSucceeded`, `PaymentFailed`, `PaymentExpired`, `NoAction`.

Слова нет в карте — исход колбэка `Unknown`. Исключение из-за этого не бросается.

## PaymentMethods

Ключ таблицы — код метода. В значении:

- `ProviderMethod` — как метод называется у кассы;
- `Currency` — валюта;
- `DetailsType` — `Card`, `Phone`, `BankAccount` или `Qr`;
- `Account` — имя набора из `Accounts`;
- `MinAmount` и `MaxAmount` — нижняя и верхняя сумма в основных единицах, границы входят. Ноль или отсутствие поля значит, что границы с этой стороны нет.
- `AmountStep` — шаг суммы в основных единицах: сумма должна делиться на него без остатка, иначе метод отвечает `Declined` с кодом `Method.Rejected` и HTTP-вызова нет. Ноль или отсутствие поля значит, что шага нет; отрицательное число — ошибка загрузки.

## Закрытые списки

Писать можно только эти слова. Опечатка видна на старте.

- `Capabilities`: `PayinExecute`, `PayinCallback`, `PayoutExecute`, `PayoutCallback`.
- `Auth.Kind`: `None`, `Bearer`, `Header`.
- `Signing.*.Algorithm`: `None`, `HmacSha256`, `HmacSha512`, `Md5`, `Sha256`.
- `Signing.*.Encoding`: `HexLower`, `HexUpper`, `Base64`.
- `ContentType`: `Json`, `Form`.
- `Callback.Format`: `Json`, `Form`.
- `DetailsType` и тип реквизита: `Card`, `Phone`, `BankAccount`, `Qr`.
- `Outcome.Result`: `Accepted`, `Declined`, `Error`.
- `StatusMap`: `PaymentSucceeded`, `PaymentFailed`, `PaymentExpired`, `NoAction`.
- `AmountUnit`: `Major`, `Minor`.

## Файлы кейсов

Поведение секции лежит в `tests/Cases/<Секция>.json`. Файл один на секцию. Кейс — объект с такими полями:

- `name` — имя кейса;
- `kind` — `payin`, `payout`, `payin-callback` или `payout-callback`;
- `firm` — фирма; в образце это `firm-a`;
- `clock` — момент, который видят часы в этом кейсе;
- `note` — короткая пометка;
- `settings` — перекрытие настроек, без секретов;
- `request` — запрос на create, либо вместо него `callback` — колбэк, как он пришёл (`body`, `headers`, `query`, `path`);
- `replies` — ответы кассы по порядку вызовов; у ответа есть `status`, `body`, `path`, `httpMethod`, `contentType`;
- `expected` — какие вызовы должны уйти и какой исход должен вернуться.

Переменная окружения `CASES_UPDATE=<Секция>` записывает ожидания названной секции по текущему прогону. Секретов в файле нет: на их месте ссылка `$secret:`.

Тест компонента смотрит на искусственное определение `tests/fixtures/scheme.json`, не на файл живой секции.

## Правила кода

1. Исход платежа — значение, не исключение.
2. Неизвестный статус колбэка — `Unknown`, не падение.
3. Имени кассы в `src/` нет. Имя живёт в `integrations/<имя>.json`, в кейсах этой секции и в тексте задания. Это держит `tools/check-hygiene.sh`.

## Новое слово закрытого списка

Слово добавляется сразу в четырёх местах. Значение в enum или строка в списке допустимых слов. Разбор, который это слово узнаёт. Одна строка в этом файле, в списке выше. Тест на фикстуре `tests/fixtures/scheme.json`, и в этом тесте нет имени кассы.

## Чего в движке нет

Этих четырёх вещей в движке нет. Схема их не описывает, код их не делает.

1. Подпись по компактному JSON, у которого ключи стоят в отсортированном порядке.
2. Пары `key=value`, склеенные так, что между парами нет разделителя.
3. Тело HTTP-ответа на колбэк, взятое из конфига.
4. Повторный вызов после create, чтобы забрать реквизит.
